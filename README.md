# 🥗 NutriAI — AI-Powered Nutrition Tracker

NutriAI is a complete personal nutrition tracking web app. Search a curated database of **870 Indian & global dishes**, log meals by tap or voice, analyze free-text meal descriptions with AI, and track calories, macros, hydration and weight against personalized goals.

## Features

- **Food search & logging** — multi-token search across the 870-dish database with health scores (0–100) and good/warn/bad badges.
- **AI meal analysis** — type "2 idlis with sambar and coconut chutney" and Gemini splits it into items with per-item and total nutrients.
- **Voice input** — hands-free meal description and search via the Web Speech API.
- **Onboarding & goals** — 6-step wizard computes personalized calorie/macro/water/weight targets using the Mifflin–St Jeor BMR/TDEE formula.
- **Dashboard** — macro rings, weekly calorie chart, meal distribution, health alerts, and today's logged foods.
- **Meal planner** — auto-generated weekly plans with meal swapping.
- **Analytics, history, water & weight trackers, achievements** — 30-day history review, hydration streaks, weight progress charts.
- **AI assistant** — evidence-based nutrition coach chat.
- **Agent integrations (MCP)** — an OAuth-protected MCP server at `/mcp` (`search_foods`, `log_food`, `log_custom_food`, `list_food_log`, `delete_log_entry`) so external assistants like ChatGPT, Claude or Cursor can act as the signed-in user, plus browser-local WebMCP tools on the food log and dashboard.

## Tech stack

| Layer | Tech |
| --- | --- |
| Frontend | React 19, TypeScript, Vite, TanStack Start (SSR + server functions) |
| Styling | Tailwind CSS v4, custom glassmorphic light theme (OKLCH tokens) |
| Charts | Recharts, custom SVG macro rings |
| AI | Lovable AI Gateway (Google Gemini) for chat & meal analysis |
| Backend | Lovable Cloud (managed Supabase) — auth, Postgres with RLS, per-user sync |
| Data | 870-dish nutrition dataset (`src/data/foods.ts`) |

## Getting started

```bash
bun install        # or npm install
bun dev            # start the dev server
```

The app reads its Supabase connection from `VITE_SUPABASE_URL` / `VITE_SUPABASE_PUBLISHABLE_KEY` (auto-generated by Lovable Cloud in `.env`).

## Project structure

```
src/
  components/       # FoodCard, MacroRing, HealthAlerts, VoiceInput, 3D hero, sidebar…
  data/foods.ts     # 870-dish nutrition dataset with health scoring
  lib/              # goals (BMR/TDEE), food-log persistence + Supabase sync, MCP tools
  routes/           # TanStack file routes: landing, auth, onboarding, dashboard,
                    # food-log, analytics, meal-planner, recipes, water, weight,
                    # achievements, history, profile, AI assistant, MCP & OAuth routes
```

## Data & privacy

Food logs, water and weight entries are stored per user and protected by row-level security; every request acts as the signed-in user. The MCP server requires OAuth — no shared tokens or public data access.
